# 虚构回顾性队列项目进度地图

## 当前请求

用户问：“这个项目现在到哪一步，下一步做什么？”本轮只导航，不执行建议。

## 已读取状态

- 研究方案存在，设计和主要结局已由项目负责人确认；
- 方法草稿存在，但尚未与最终数据字典核对；
- 原始数据存在，未完成统计分析；
- 目标期刊未确定；
- 伦理批件号记录在稿件中，但尚未对照原件。

## 进度摘要

| 环节 | 状态 | 依据 |
|---|---|---|
| 研究问题与设计 | complete | 方案 + 人工确认记录 |
| 伦理与注册 | needs_confirmation | 伦理编号未对照原件；注册对该项目是否适用待判断 |
| 数据充分性 | in_progress | 数据文件存在，尚未做只读质量盘点 |
| 方法 | in_progress | 草稿存在，未与数据字典核对 |
| 统计分析 | not_started | 无分析计划批准记录或输出 |
| 结果/讨论/摘要 | not_started | 无对应工件 |
| 目标期刊 | not_started | 未选择 |

## 关键风险

1. 伦理编号未对照原件，任何投稿材料都不能把它写成已确认；
2. 数据文件存在不等于足以回答研究问题，需先检查变量、缺失和事件数。

## 推荐下一步

- Skill：`dyz-med-data-adequacy`
- 为什么现在做：在正式建模和继续完善方法前，先确认现有数据能否支持主要问题；
- 所需输入：只读数据、数据字典、方案和主要结局；
- 预期产出：可回答问题、缺失变量和关键风险清单；
- 人工确认点：项目负责人确认变量含义与主要结局。

地图到此结束，不自动执行下一 Skill。

## 后续自然语言请求的边界示例

以下为预期路由说明，未在真实宿主执行：

- “请检查这些数据够不够回答主要问题。”直接选 `dyz-med-data-adequacy`，只做充分性评估，不启动统计建模。
- “帮我分析这批数据。”选 `dyz-med-analyze`，先只读检查与拟定计划；没有对当前计划的明确批准就不执行分析。
- “研究已经做完，请初始化论文写作项目。”选 `dyz-med-init`，沿用已有设计和数据或结果，不重新创造研究方案。
- “先从零查这个课题的文献。”选 `dyz-med-cnki`；“精读候选表里这三篇全文。”选 `dyz-med-key-literature`。
- “把现有摘要译成英文，不改内容。”选 `dyz-med-translate`，不重写结论或生成新的摘要结果。
- “请导出本地 Word 文件。”选 `dyz-med-export`，不上传期刊；“准备投稿信和题名页。”选 `dyz-med-submit`，只生成本地材料。
- “帮我处理一下论文。”若无更多上下文，澄清诊断、翻译或修订目的，不默认执行全文改写。

这些请求无需包含 Skill 名称；选中后仍核对所需材料与授权，不自动进入下一阶段。
