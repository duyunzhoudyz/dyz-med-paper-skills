# 科研项目管理与可追溯性实践说明

`dyz-med-orchestrator` 本身不对应某一个单一的报告规范（它是流程导航工具，不是稿件内容规范），因此
这里列出的是与"研究项目状态管理、进度追踪、可追溯性"相关的通用医学科研管理实践，供理解本技能
设计思路的背景参考，不是本技能强制执行的清单。

## 研究可追溯性相关的通用实践
- **ICH E6(R3) Good Clinical Practice 与临床试验主文件实践**——临床试验管理强调关键文件、
  数据和决策的可追溯性。
  `paper/project-passport.yaml`（由 `dyz-med-passport` 维护，本技能读取）在设计精神上借鉴了"集中
  记录关键状态与决策"这一思路，但本技能包并非临床试验管理系统，不等同于正式的Trial Master
  File。
- **PRISMA 2020 声明中的"流程图"理念**——系统综述/meta分析要求用流程图记录文献筛选各阶段的
  数量变化，是一种"阶段化、可视化呈现研究进展"的报告惯例。本技能的"进度地图"在呈现形式上借鉴
  了"分阶段可视化状态"这一通用思路，但适用范围是整个写作项目管理，而非专指文献筛选流程（文献
  筛选流程图本身由 `dyz-med-flowchart`/`dyz-med-screening-pipeline` 负责）。

## 研究注册与阶段确认的通用实践
- **临床试验预注册（如ClinicalTrials.gov、中国临床试验注册中心 ChiCTR）**——RCT等前瞻性试验
  通常要求在入组前完成注册，这是本技能"REGISTRATION"阶段检测逻辑的现实依据（详见
  `dyz-med-registration`）。
- **人体研究伦理审查（源自赫尔辛基宣言确立的原则）**——研究方案需经伦理委员会批准/知情同意，
  是本技能在风险提示中"确认伦理声明状态"这一项的现实依据。

## 意图调用与流程授权

本库区分“由宿主按用户意图选择技能”和“自动串联科研阶段”。前者可由明确的自然语言任务触发，无需
手工输入 Skill 名称；后者不因技能被选中而获得授权。清晰任务直接匹配职责最窄的技能，状态或下一步
查询仅推荐；只有上下文不足以区分目标时才澄清。

- 选题未成形用 `dyz-med-ideate`；已有问题、设计与数据或结果，初始化论文写作项目用 `dyz-med-init`。
- 从零检索用 `dyz-med-cnki`；已有候选池或明确论文的全文精读用 `dyz-med-key-literature`。
- 忠实翻译用 `dyz-med-translate`；明确实质修订用 `dyz-med-revision` 或职责更窄的分节技能。
- 统计执行须有针对当前计划的明确批准，意图识别只能触发该技能内允许的前置检查与计划步骤。
- `dyz-med-export` 的本地导出和 `dyz-med-submit` 的本地材料准备不包含外部上传、发送或正式提交；外部动作
  需要另行明确授权及最终确认。

### 宿主兼容性与验证限制

[Codex 官方 Skills 文档](https://developers.openai.com/codex/skills.md)说明可根据描述隐式选择技能，
`agents/openai.yaml` 中 `policy.allow_implicit_invocation` 默认是 `true`。本库在32份配置中显式
保留此允许策略，但该字段属于兼容宿主的配置，不是跨宿主保证，也不是自带意图分类器。Breezell 或
其他宿主是否读取、安装并索引本库，需分别验证；仅文件存在不能证明实际可调用。

结构校验命令：在仓库根目录运行 `python scripts/validate_skills.py`。它只读取文件，检查 frontmatter、
调用配置、YAML/JSON 和实际 Markdown 资源链接，不安装依赖，也不调用模型或外部服务。
[意图路由用例](../../tests/fixtures/intent-routing.json)标记为 `verification_status: not_run`，
是待执行的语义回归规格；结构通过不等于选中准确率或宿主行为验证。未配置分词器时 token 预算记为
`NOT_MEASURED`，正文行数检查不能替代 token 测量。

## 说明
以上内容是背景性、说明性的实践参考，用于帮助理解为什么本技能的进度地图会包含"注册状态""伦理
确认"这类字段，并不代表 `dyz-med-orchestrator` 本身实现或强制执行了这些规范的具体流程——具体的
注册核对、伦理审查协助分别由 `dyz-med-registration`、各分节撰写技能在其专属环节中处理。
