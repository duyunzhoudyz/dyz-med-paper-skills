# dyz-med-flowchart 完整示例（教学演示）

> **本示例为教学演示，涉及的研究课题、受试者数量均为虚构，不对应任何真实已发表研究，仅用于演示
> dyz-med-flowchart 的工作方式。**

## 场景（虚构课题）：RCT，CONSORT 2025 流程图

虚构课题："某新型降压药物对轻度高血压患者血压控制效果"的随机对照试验。

## Phase 1：收集流程数据（虚构数值）

- 评估资格：210例（虚构）
- 排除：30例（不符合纳入标准18例、拒绝参与9例、其他原因3例，虚构）
- 随机分配：180例（虚构），90例/组
- A组（试验药）接受干预：90例；B组（安慰剂）接受干预：90例（虚构）
- 失访：A组6个月随访失访5例（搬迁3例、撤回知情同意2例）；B组失访7例（虚构）
- 主要分析集：本例必须按方案另行确认。不能仅因为 A 组 85 例、B 组 83 例完成随访，就把这 168 例自动
  标成 ITT 或主要分析集。

## Phase 2：生成流程叙述（虚构示例文字）

"共210例患者接受资格评估（虚构），其中30例被排除（不符合纳入标准18例，拒绝参与9例，其他原因3例）。
180例随机分为两组，每组90例。随访6个月期间，试验组5例、对照组7例失访。主要分析集及其分母按预设
estimand 和实际分析输出另行报告。"

## Phase 3：分母一致性核查（虚构）

- 核查随机总数是否等于两组分配数，并分别核查随访完成数、Table 1 分母和模型分母对应哪个分析集。
- 若 Table 1、流程图与模型输出分母不同，先判断是否为合理的分析集差异；不能直接修改数字使两处“对上”。

## Phase 4：记录失访并交接影响分析（虚构）

失访率 = 12/180 ≈ 6.7%（虚构）。流程图只报告人数、时间点和原因；是否需要插补或敏感性分析取决于
estimand、缺失机制、结局可得性及预设方案，交给统计分析环节判断，不套用固定比例阈值。

## Phase 5：生成CONSORT流程图（虚构，Mermaid片段示意）

```
flowchart TD
    A[评估资格 n=210] --> B[排除 n=30]
    A --> C[随机分配 n=180]
    C --> D[试验组 n=90]
    C --> E[对照组 n=90]
    D --> F[失访 n=5] 
    D --> G[6个月随访资料可得 n=85]
    E --> H[失访 n=7]
    E --> I[6个月随访资料可得 n=83]
```

## 小结

本示例展示了从流程数据收集、叙述生成、分母核查、失访记录到最终 Mermaid 图生成的完整链路。
所有数字均为虚构占位，实际使用时必须替换为真实研究的流程数据。对系统综述/范围综述场景，请参见
`/dyz-med-screening-pipeline` 的示例了解 `prisma-counts.yaml` 的产出方式，本技能只负责读取而非重新
计算这些数字。
