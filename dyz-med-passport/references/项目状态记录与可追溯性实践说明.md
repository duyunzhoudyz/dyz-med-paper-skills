# 项目状态记录与可追溯性实践说明

`dyz-med-passport` 是一个内部状态记录机制，不对应某一个具体的报告规范。以下是与"研究项目状态记录、
人工确认追溯"相关的通用医学科研管理实践，用于说明本机制的设计背景，不是本机制强制实现或认证的
标准。

## 可追溯性记录的通用理念
- **ICH E6(R3) Good Clinical Practice**——临床试验行为规范中强调数据治理、来源可查和过程留痕。
  任何关键决定和数据状态都应当有据可查、可追溯到原始来源。
  `project-passport.yaml` 中已确认事实须保留来源、人工确认须绑定版本且不能凭空产生的设计逻辑，
  借鉴了这一"可追溯性"的精神，但本机制是论文写作辅助工具的内部记录，不是正式的临床试验管理
  系统，也不能替代真正的GCP合规记录。
- **赫尔辛基宣言确立的知情同意与伦理审查原则**——是本机制记录伦理事实与人工来源的背景依据。
  schema 1.1 使用有 targets、role、confirmed_at 和 source 的 `human_approvals`；旧布尔确认不能
  替代来源。研究参与同意与患者发表同意分开，适用性待有资质人员复核，不由工具推定批准或豁免。

## 人工确认与AI辅助工作的责任边界
- **COPE 关于作者责任的指导原则**——强调无论使用何种工具辅助写作/分析，最终的内容责任由作者
  承担。`dyz-med-passport` 区分"操作者（operator，驱动AI工具的人）"与"临床确认人（clinical
  confirmer，对数据真实性/伦理合规做出判断的人，可能是同一人也可能不是）"这一设计，呼应了
  "AI辅助不能替代人类责任主体"这一原则——本机制记录谁做出了确认，但不代替任何人做出确认。

## 项目管理中的阶段化状态追踪
- **一般科研项目管理实践中的里程碑/阶段追踪（stage-gate）方法**——广泛应用于科研项目管理（不
  限于医学领域），将复杂项目拆解为可追踪的节点。本机制以 `artifacts`、`checks`、`open_items`
  与 `history` 记录实际工件、检查及问题，不定义自动阶段流水线。旧 `pipeline.stage` / `quality_gates`
  仅可保留为历史扩展，不是当前 schema 1.1 的状态消费或门禁依据。
  以[工件与版本绑定合同](artifact-contract.md)为字段准绳：执行状态、适用性、领域结论和逐条 freshness
  分开；回复不等于 verified_closed，退出码 0 不等于科学 PASS，人工记录 recorded_not_authenticated
  不等于授权认证。这种追溯思路不是行业认证，不编造具体标准名称/发布机构/年份。

## 说明
以上内容说明本机制"为什么要记录这些字段"，帮助理解其设计动机，并不代表 `dyz-med-passport` 本身是
一套正式的临床试验管理系统或认证工具——它是论文写作过程中的辅助性状态记录文件。
