# 终稿连贯性/一致性检查清单

> 用途说明：这份清单用于**检查已经写好的稿件**（各节分稿已齐全，或已用 `/dyz-med-write` 生成过一次性
> 初稿），核对拼接/整合之后是否前后一致；它不是用来起草任何一节内容的骨架模板。使用方式是逐条对照
> 现有文本打勾，标记出不一致之处，再决定要不要采纳修改建议——全部条目都是提示性质，不做自动阻断或
> 自动改写。

## 使用时机

- 各节（引言/方法/结果/讨论/摘要）都已经用各自的分节技能或用户自己写完之后。
- 或者 `/dyz-med-write` 已经生成过一次性初稿之后，准备定稿前的最后一遍通读。

## 一、术语一致性核对

- [ ] 同一个概念在全文中是否用了同一个术语？（例如"胰十二指肠切除术"全文是否统一用同一简称，
      不要一节用"PD"、另一节用"Whipple手术"却未说明是同一手术）
- [ ] 手术组/对照组的命名是否全文统一？（例如"腹腔镜组 vs 开腹组"不要在结果部分变成
      "微创组 vs 传统组"却没有说明对应关系）
- [ ] 结局指标的名称是否全文一致？（例如"术后30天并发症率"不要在摘要里变成"围手术期并发症率"而
      指代不清是否为同一定义）
- [ ] 统计术语使用是否一致？（例如"比值比(OR)"和"相对危险度(RR)"不应混用于指代同一分析结果）

## 二、数值一致性核对（与 `structured_results.yaml` 等原始来源核对）

- [ ] 摘要（Abstract）里出现的每一个数字（样本量、率、效应量、置信区间、P值）是否能在结果部分
      正文中找到完全一致的对应数字？
- [ ] 结果部分正文中的数字是否与 `paper/data/stats/structured_results.yaml` /
      `analysis_results.json` 逐一核对一致？
- [ ] 讨论部分引用"本研究结果"时提到的数字，是否与结果部分一致（没有被无意改写或四舍五入方式
      不一致）？
- [ ] 表1（基线特征）中的数值是否与 `paper/data/tables/table1.csv` 一致，且方法部分描述的样本量
      与表1一致？
- [ ] 各节报告的置信区间格式（如 95% CI）是否全文统一（例如都用"OR 2.90 (95%CI 1.90–4.42)"这种
      格式，不要一处用"–"一处用"~"）？

## 三、缩写与定义核对

- [ ] 每个缩写（如 PD、LR、EPV、RFS）是否在全文**第一次出现处**给出了全称定义？
- [ ] 摘要和正文是否各自独立满足"首次出现即定义"（有些期刊要求摘要和正文分别独立定义一次）？
- [ ] 是否存在同一缩写在不同节里指代不同含义的情况？

## 四、图表编号核对

- [ ] `paper/data/figures/display-items-manifest.yaml` 中列出的每一个图/表，是否都在正文某处被
      提及（编号+一句话指向，而不是逐条罗列图表内容）？
- [ ] 正文中提到的图表编号（如"见图3"）是否确实对应 manifest 里存在的图表，没有编号错位？
- [ ] 是否存在正文引用了 manifest 里不存在的图表编号，或 manifest 里的图表从未被正文提及？

## 五、FORBIDDEN 内容自查（这些内容不该出现在正文里）

- [ ] 正文中是否混入了流程注释/写作步骤说明（如"本步骤""下一步我们将"）？
- [ ] 正文中是否混入了QA检查清单式的罗列（例如把图表逐项列出的清单直接粘进了正文）？
- [ ] AI 使用披露是否与实际使用情况一致，并放在目标期刊当前要求的位置？不要因为统稿而删除，
      也不要在期刊未要求的位置重复插入。
- [ ] Results 部分是否混入了解读性措辞（"suggests/indicates"等应属于 Discussion 的语言）？

## 六、检查完成后

对每一处标记出的不一致，写清楚：不一致的具体位置（哪一节、哪一句）、以哪个来源为准（通常是
`structured_results.yaml`/`display-items-manifest.yaml`/`key-literature-map.yaml`）、建议的
具体改法。是否采纳、何时修改，由用户决定。
