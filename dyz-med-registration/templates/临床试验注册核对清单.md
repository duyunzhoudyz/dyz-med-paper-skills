# 临床试验注册核对清单

> 来源：WHO Trial Registration Data Set（TRDS，Version 1.3.1，共24项，WHO ICTRP官方发布）+
> ClinicalTrials.gov 补充字段 + 当前 CONSORT 注册报告要求。用途：核查一项试验注册记录是否完整，
> 并与稿件描述逐项交叉核对；字段含义按所用平台原始记录映射。

## 核查范围与事实来源

- 注册号及格式检查结果：<格式检查只用于选择入口，不证明真实注册>
- 平台、查询条件、检索日期、范围、取得方式与记录版本：<实际执行情况；未执行则说明>
- 检索状态：<found / not_found / access_blocked / not_checked>
- 来源 URL/文件与定位、访问失败或未检查原因：<实际依据；不补造 API 调用>
- 已核实研究事实：<机构、编号、日期及字段含义等逐项列证据；未核实字段留空或注明未核实>
- 注册时间判断：<prospective / retrospective / uncertain；注明日期比较与政策依据>

| 检索状态 | 含义 | 能报告的范围 |
|---|---|---|
| `found` | 取得官方记录并确认与目标研究对应 | 只报告实际核实的字段，不自动通过全部一致性检查 |
| `not_found` | 正常完成所列检索，未找到匹配记录 | 报告本次条件与范围内未找到，不能推断研究未注册 |
| `access_blocked` | 请求失败或受访问限制，核查未完成 | 报告限制与补充材料需求，不能当作零结果 |
| `not_checked` | 未执行核查 | 报告原因与待检查范围，不能声称已检索 |

检索状态与注册事实分开；未取得必要日期或政策依据时，注册时间为 `uncertain`。
若其他平台提供记录，独立核对其真实性、研究对应关系与适用性，不能以 OSF 未命中否定它。

## 第二部分：ClinicalTrials.gov 补充核对字段（CT.gov API v2 常见字段）

| 字段 | 注册原值 | 稿件原值 | 一致性状态 | 双方定位、理由与处理 |

| PrimaryOutcomeMeasure | | | | |

| HasResults | | | | |
| ResultsFirstPostDate | | | | |
| LastUpdatePostDate | | | | |

以上两表只使用正文的五类一致性状态：

- `MATCH`：核对范围内同一口径、定义、时点与数值一致；小差异不等于一致。
- `EXPLAINED_CHANGE`：差异有可定位依据和经核对的解释；保留双方原值、差值和解释证据。
- `UNEXPLAINED_CHANGE`：已确认差异，但尚无证据支持的解释，不因作者接受风险关闭。
- `NOT_REPORTED`：已注册项目在已核查稿件及补充材料中缺报，且无证据支持的未报告解释。
- `UNVERIFIED`：资料、定义或可比口径不足，说明缺失内容。

样本量保留计划数、实际入组数及分析集人数各自口径。差值 = 稿件数 - 注册数；同时列绝对差。
百分比 = 差值 / 注册数 × 100%，注明分母；注册数为零或未知时不计算。
例如实际入组注册236、稿件235：差值 -1，绝对差1，-0.42%（分母236），无解释时为
`UNEXPLAINED_CHANGE`。有解释时改为 `EXPLAINED_CHANGE`，不能覆盖原值或把差值改为零。

## 第三部分：风险与待核查项

| 风险项 | 判定条件 | 本试验依据与待办 |
|---|---|---|
| DESIGN-007 结局切换 | 主要结局注册记录与稿件描述不一致；差异不自动证明不当行为 | |
| ETHICS-002 回顾性注册 | 按已核实日期与适用政策判断，日期不足则未核实 | |
| 样本量差异 | 逐项列出已确认差异及解释证据；不用差异阈值自动判一致或违规 | |
| 已注册次要结局缺报 | 单列 `NOT_REPORTED`，索取真实报告或证据支持的未报告解释；不能编造补报 | |
| 结果发布义务待核实 | 按适用的注册平台、资助方或监管规则核实 | |

主要结局匹配不能关闭全部选择性报告风险。承诺补报、笼统添加局限性或作者接受风险不等于问题解决；
仅在收到可定位的报告或解释证据后重新核对相应项目。

## 第四部分：注册声明生成

使用前对照当前 CONSORT、目标期刊和平台要求。只有实际核实的字段可进入最终声明；格式有效、
`not_found`、`access_blocked` 或 `not_checked` 均不能用来生成确定性注册事实。

已核实声明模板：
> “本试验已在 [已核实注册机构] 注册（注册号：[已核实编号]），[平台日期字段含义]为 [已核实日期]。”

只有方案内容和访问地址也已核实，才追加方案可获取说明；注册页面本身不证明完整方案可获取。
未知字段保留 `TBD` 于工作稿并列待办，不能将占位声明作为已核实的最终文本。

## 第五部分：适用的非试验预注册核对

按研究类型、实际平台和适用期刊要求选择 OSF、PROSPERO 或其他预注册平台，不要求所有研究使用
OSF，也不把所有非试验研究的预注册当作统一强制义务。复用上面的四类检索状态，不另建状态体系。

| 检查项 | 记录 |
|---|---|
| 平台及选择理由 | <实际平台、研究类型与适用要求> |
| 检索日期、条件、范围与来源定位 | <实际执行情况；未执行则说明> |
| 检索状态 | <found / not_found / access_blocked / not_checked> |
| 已核实研究事实 | <实际取得并核实的记录、日期及出处；未知不补造> |
| 预注册时间与分析开始时间 | <各自日期、来源、比较结论或 uncertain> |
| 结局及分析计划对照 | <沿用五类一致性状态，列差异和定位> |
| 尚需作者或平台提供的材料 | <记录链接、正式导出、可靠日期或解释> |

无结果时只能写“在 [日期/平台/条件/范围] 未检索到匹配记录”；访问失败时写明失败和未完成范围；
未检查时如实写未检查。均不能据此写“本研究未预注册”或“方案偏离无法系统评估”。
若作者另行提供未预注册的事实说明，保留说明来源并按实际方案材料与适用要求评估，不从搜索缺失推导。
