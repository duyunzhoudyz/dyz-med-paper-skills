---
title: Response to Reviewers for Medical Manuscripts
description: Organize reviewer comments, plan manuscript revisions and draft a point-by-point response with change locations and clearly marked unfinished work.
---
Use `dyz-med-revision` to revise a manuscript, prepare responses or adapt it for another journal. If a rejection letter leaves the main problem unclear, start with a read-only `manuscript-diagnose` assessment.

## Gather the inputs

Provide the current manuscript, editor letter, complete comments separated by reviewer, journal requirements and changes already made. Keep version identifiers and page or line references for reliable locations.

> Number the comments and build a revision plan. Separate wording changes from facts needing confirmation and requests requiring reanalysis. Describe a change as completed only after it has actually been made.

## Build a response matrix

| Field | Content |
|---|---|
| Identifier and original comment | One-to-one correspondence with the decision letter |
| Issue and action | Explanation, text change, analysis or supported disagreement |
| Manuscript change | Specific modification and location |
| Draft response | Answer, rationale and pointer to the revision |
| Status | Completed, awaiting confirmation or pending execution |

Do not turn a planned analysis into a claim that it was performed. Confirm new data, reanalysis, ethics, authorship or other source facts before recording actual results.

## Write responses that point to changes

Answer the substantive question and identify the change and its location. If disagreeing, explain the reason in relation to the design and evidence, and consider clarifying the manuscript. Courtesy alone does not answer the comment.

> Update the responses using the completed manuscript changes. Include a location for each change and retain unfinished items as pending. Compare response commitments against the manuscript and list what remains.

## Check and deliver

Deliver the revised manuscript, response letter, change log and open-task list. Reconcile the abstract, results, discussion and figures. `submit` prepares local submission materials; external upload or final submission requires explicit authorization and final confirmation.
